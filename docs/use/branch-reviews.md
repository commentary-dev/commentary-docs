Paste a GitHub repository, branch, folder, or Markdown/MDX/HTML file URL on the home page to review a document outside a PR. For Azure DevOps, prefer a project-scoped repository, branch, folder, or file URL.

The document surface supports branch and commit inspection, file navigation, rendered Preview, Raw source, and app-native threads. It does not have a provider **Submit review** action: comments stay in Commentary and do not create commits or PR comments.

Use branch reviews for early feedback on ADRs, plans, docs maintenance, generated reports, or knowledge-base updates. Refresh after the source changes and revisit the current exact version. Review progress helps each reviewer resume; shared repository update timestamps do not stand in for your personal visit history.

For work not yet in Git, use a [Draft Review](draft-reviews.md). For the end-to-end flow, see [review a branch document before a PR](../workflows/review-a-branch-document.md).
