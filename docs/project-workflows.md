# Plan and review an initiative

## A terminal-free PM workflow

Create a [Project](projects.md) in the intended workspace. Write the outcome, audience and decision needed in Overview. Link an existing document, Form, Research Study or review through the authorized picker. Add a [Tracker](trackers.md) only when structured work helps: a checklist can be enough. Choose fields for meaningful deliverables rather than importing a methodology.

Prepare a [review package](review-packages.md) whose first page explains scope, alternatives, residual risk and the requested decision. Put detailed evidence behind navigable pages. Create a [Review Session](project-review-sessions.md) selecting exact ready revisions, and invite eligible reviewers. Review rendered pages and native threads; use source exploration only where exact implementation matters.

After feedback, publish a new immutable package revision and revise the Session composition, preserving unaffected exact targets. Read the current manifest and request fresh acceptance for changed material. The eligible human responds in Inbox. Replies discuss the current instance; Teach this agent guides future behavior. An agent's completion report does not accept the work.

## Read progress honestly

Execution is configured/user-reported. Artifact existence is resolved independently. Review status comes from review facts. Acceptance comes from eligible human Decisions on exact targets. Verification has its own provenance and scope. A Board move or a 100% checklist cannot stand in for any of these dimensions.

Tracker record-to-Session relations can connect work to exact reviews. Configured progress policies may apply conditional execution transitions; conflicts require reconciliation. Routine edits do not generate a new Inbox post. Existing actionable Interactions remain the attention surface. See [evidence](project-evidence.md) and [acceptance and impact](project-acceptance.md).

If a participant loses original source access, the Project does not restore it. Resolve source permissions with the owner, then reload. Never include private titles in a workaround or publish an alternate public copy to bypass a denial.
